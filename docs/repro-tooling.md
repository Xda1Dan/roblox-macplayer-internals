# The reproduction tooling (`vm-repro/`)

> What this is: the working C++ reproduction of everything this project has
> reverse engineered — not illustrations, but tested implementations of the
> real formats and state machines. Every piece ships with a test suite that
> verifies it against ground truth: bytes dumped from the player binary,
> official cipher test vectors, and the reference Luau loader.
>
> Everything here is built from first-hand analysis documented across the
> site; nothing is copied from proprietary source.

## What is implemented

| Layer | Status |
|---|---|
| Opcode triple-numbering (canonical / wire / vmop) + the `T`/`R` scramble tables | done, tested — tables dumped from the binary |
| Disassembler for all 93 opcodes, with constant resolution | done, tested |
| Struct layouts (`lua_State`, `CallInfo`, `Proto`, `Closure`, `TString`, `Table`) | done — offset tables with static asserts |
| RSB1 script-container pipeline (scramble, key recovery, XXH32 integrity, zstd) | done, tested — checksum verified against the binary's *own machine code*, executed in the test |
| ScriptContext state machines (resume guard, admission, `require`) | done, tested — guard exact; admission polarity corrected (0 = allowed, 1 = blocked; no predicate is fail-closed); `require` is a behavioral model |
| RakNet datagram AEAD (ChaCha20-Poly1305, custom framing) | done, tested — RFC 8439 primitive vectors + an independent known-answer vector; the 4-byte nonce suffix is documented as unused by the primitives |
| LBC serialized-chunk reader + constant-aware disassembly | done, tested — cross-checked against the reference loader; header-only opcode conversion (AUX words untouched) |
| `luau_load`-equivalent loader (wire→vmop rewrite, atom pass, closure tree) | **done, tested** (`src/loader.cpp`) — canonical and wire inputs produce identical VMOP code + disassembly |
| SigGuard bytecode auth (mode chain, SHA-256, table MAC) | done, tested — packed table fixture from the binary; MAC cross-checked against an independent Python transcription |
| Binary audit (`rbxaudit`) | done — re-checks the target's tables, dispatch handlers, SigGuard blob, checksum code, and gate call site |
| `luau_load`-equivalent loader, interpreter core | planned |

## The full delivery pipeline, end to end

This is the same journey a script takes from the compiler to the
interpreter, reproduced with the tooling:

```sh
# 1. compile Lua with the version-matched reference compiler
luau-compile --binary script.lua > script.lbc

# 2. scramble the opcode bytes (canonical -> wire) and wrap in an
#    RSB1 container — what the server ships
tools/rbxrsb1 encode --size0 --wire script.lbc -o script.container

# 3. decode on the "client" side
tools/rbxrsb1 decode script.container -o script.wire.lbc

# 4. parse the chunk and disassemble — the wire numbering resolves back
#    to identical canonical output
tools/rbxdis chunk --openc=wire script.wire.lbc
```

The test suite asserts that step 4's output is byte-identical to
disassembling the original canonical chunk.

## How things are verified

A few highlights of the test discipline in `tests/`:

- **The binary certifies the checksum.** The container-integrity checksum
  (`FUN_103222533`) is pure computation, so its 318 bytes of machine code
  were extracted from the player, mapped at runtime, and *executed* against
  our implementation across a 1000+-case sweep.
- **Official vectors + an independent model for the AEAD.** The primitives
  are checked against RFC 8439 (ChaCha20 block, Poly1305) and the custom
  framing against a known-answer vector generated by a separate Python
  model of the decompiled construction. The model pins the counter-0 state
  layout (8-byte nonce) and the payload counter start of 1.
- **The reference loader as ground truth.** The chunk reader was
  cross-checked against the reference `luau_load`/`luau-compile` output,
  which caught three format subtleties (1-based string ids, proto size
  fields, import ids).
- **The target certifies the SigGuard tables.** The packed 99 KB blob is a
  committed fixture with a recorded SHA-256; `rbxaudit` re-hashes the
  corresponding binary region. The MAC expansion is cross-checked against
  an independent Python transcription for fixed selectors.
- **The target certifies the ChaCha20 core.** The binary's ChaCha block
  function (`FUN_10183c095`) is extracted — machine code, its four
  rip-relative shuffle constants, and a six-entry rip-relative patch table —
  into a committed fixture. The test maps it into a scratch arena, patches
  the displacements, and runs it against the reproduction across a
  key/nonce/length sweep, counter continuity across calls, and in-place
  XOR. Pinned contract: `core(state, a, b, len)` writes `b = a ^ ks(state)`
  and advances the state's 64-bit counter by `ceil(len/64)`. (Same trick as
  the xxHash32 test.)

## Building

```sh
cd vm-repro
make test      # builds and runs the eight test suites
make demo      # disassemble a wire-encoded sample program
make audit BINARY=/path/to/RobloxPlayer
```

Requires only a C++20 compiler, `make`, and (optionally) `libzstd` for the
compressed-container path — loaded at runtime, no headers needed. `make
audit` is the only target that needs the target binary.

## Layout

```text
include/rbxvm/   opcode.hpp, scramble.hpp, insn.hpp, ptrenc.hpp,
                 layouts.hpp, disasm.hpp, rsb1.hpp, zstd_loader.hpp,
                 scriptctx.hpp, aead.hpp, lbc.hpp, sigguard.hpp
src/             implementations of the above
tools/           rbxdis (tables/verify/code/chunk), rbxrsb1 (containers),
                 rbxaudit (verify constants against a target binary)
tests/           eight suites + fixtures (compiled Lua, SigGuard tables,
                 extracted machine code)
```

Per-area provenance (which binary address every claim came from) lives in
the header comments of each `include/rbxvm/*.hpp` and in the research notes
under `research/vm-research/`.
